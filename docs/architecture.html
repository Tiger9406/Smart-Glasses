Smart glasses architecture

Host pipeline. UDP in, vision and audio workers, a coordinator, one OpenAI call at a time, sqlite identities, and a dashboard. Prose twin: ARCHITECTURE.md.

What it is

A device or python -m api.simulator sends UDP. VisionWorker and AudioWorker run in child processes. Coordinator reads results_queue and writes command queues. APIWorker calls OpenAI. The dashboard thread on port 8765 shows logs and ./database/identities.db. Firmware, when it is in the tree, is the device. This process is the host.

Runtime

main.py builds SharedMem, starts the dashboard thread, loads sample voices when START_WITH_SAMPLE_DATA is set, then starts the four workers and the UDP thread. __init__ runs in the parent. setup() and run() run in the child. The code does not call set_start_method. On macOS the default is spawn, so InspireFace, ONNX, and Parakeet are created in setup().

The host box is main.py: the UDP thread, four workers, and the queues in SharedMem. OpenAI is called from APIWorker after a transcript exists, and from VisionWorker only when VLM_ACTIVE is on. sqlite is the file IDENTITY_DB_PATH. The dashboard is start_monitoring_server, a daemon thread, not a separate service. Its sqlite reads do not share a transaction with the workers.

Queues and events

Seven queues. Field lists live in workers/event_definitions.md. On the wire, speech carries user_id and time_start, and vision_result faces carry user_id with no event timestamp.

vision_queue and audio_queue are capped at 100 and drop the oldest datagram when full. results_queue has three writers and one reader: Coordinator.run calls handle_event. ANALYZE_MEMORY is accepted by APIWorker and is not enqueued by the coordinator. vlm_result is also a results_queue event, written by ask_vlm inside the vision process when that path runs. log_queue is capped at 2000 and is not an input to recognition.

Ingress

udp_receiver_thread binds 0.0.0.0:8000. The first byte is HEADER_VISION (b"\x01") or HEADER_AUDIO (b"\x02"). The rest of the datagram is the payload. The simulator (python -m api.simulator) sends the same bytes from simulator_config.json.

This checkout has no hardware/ directory. The firmware imported on task/import-hardware-repo is ESP32-S3 PlatformIO. udp_send_task in hardware/src/udp.cpp prefixes JPEG with WS_FRAME_VIDEO (0x01) and PCM with WS_FRAME_AUDIO_TX (0x02). The camera task pushes JPEG from esp_camera. The audio task queues 16 kHz int16 samples. Those header values match core/config.py. The host does not import the firmware. Nothing in this tree checks that the bytes still match.

Audio

AudioWorker.run chunks PCM, runs Silero, and keeps an utterance open until silence. Parakeet transcribes the finished buffer. Redimnet embeds it. identify_speaker picks a user id.

take_chunks cuts the byte stream at chunk_bytes (160 ms at 16 kHz). hears_speech returns true if any 512-sample Silero window in that chunk is above 0.5. begin_utterance opens transcribe_stream with CONTEXT_LEFT and CONTEXT_RIGHT (64, 64) and copies pre_speech. extend_utterance zeroes silence_count. note_silence increments it and keeps the samples. finish_utterance embeds with voice_embedding and calls identify_speaker, which biases toward last_speaker when that cosine score already beats SIMILARITY_THRESHOLD (0.30). speech_event is skipped when the text is empty.

Vision

VisionWorker.run drains commands, decodes a JPEG, updates tracks, and publishes vision_result. InspireFace detects and embeds. update_tracks decides whether to keep, recheck, or drop a track_id.

recognize_frame calls detect_faces, then update_tracks. Recognition runs when user_id is still DEFAULT_ID or when recheck_interval (2.0s, set in VisionWorker.setup) has passed. best_identity keeps the best feature_comparison score above 0.5. publish_faces sends the list and does not add a timestamp. REGISTER_FACE is applied by register_tracked_face before the next frame. GET_VIDEO_CONTEXT calls ask_vlm only when VLM_ACTIVE is true. With it false, apply_vision_commands returns out of the drain. After shutdown, render_annotated_video writes the offline mp4 when SAVE_ANNOTATED_VID is set.

Coordinator

Coordinator.run only pulls results_queue and calls handle_event. Speech for an unknown voice tries a pending registration, then a visual association. Every line is recorded and sent as PARSE_INTENT.

handle_speech uses user_id, time_start, and embedding. bind_pending_voice calls pending_registration_hit with max_delay (20 seconds, set in Coordinator.setup). associate_voice counts is_speaking and presence over frames within 1 second of time_start. Faces published by update_tracks have no is_speaking key, so the 0.3 speaking branch does not see speech. The 0.8 presence branch can still return the only known person. record_transcript writes sqlite chat history only for a known user. intent_prompt prepends known names from names_in_view.

Identity registration

register_identity branches on get_user_ids_by_name. A match uses the first id where face_matches or voice_is_known is true. voice_matches compares the intent's embedding to the mean stored voice. register_unknown_face picks an unknown face on that closest frame with resolve_unknown_face and enqueues REGISTER_FACE. On that match, a self-intro whose voice is not stored enqueues REGISTER_VOICE. If that branch does not run and speaker_name is USER_NAME, attempt_voice_registration runs. create_identity registers voice immediately only when speaker_name is DEFAULT_NAME and is_self_introduction is true. USER_NAME on a new user uses the same attempt: a cached unknown embedding in [0, max_delay], or the pending record that bind_pending_voice consumes later.

One sentence, both streams

The frame path is decode_frame, recognize_frame, publish_faces, then handle_vision_result, which stamps the cache with time.time() on receipt. The audio path does not emit until finish_utterance. handle_speech prints the speaker line and enqueues PARSE_INTENT. APIWorker later writes intent. Only if that cmd is REGISTER_IDENTITY does register_identity run and possibly enqueue REGISTER_FACE or REGISTER_VOICE. SPEAK only prints. VISION_CONTEXT enqueues GET_VIDEO_CONTEXT.

API worker

APIWorker.run creates the asyncio loop and handles one llm_command_queue item at a time. PARSE_INTENT calls OpenAIClient.parse_intent. ANALYZE_MEMORY calls analyze_memory. Shaping is intent_event and memory_event in workers/api_utils/commands.py. HTTP lives in api/openai_client.py. The client is OpenAI only.

An exception in the command loop becomes one api_error on results_queue. A None intent is not queued. handle_event logs api_error and has no branch for memory_result. The aiohttp session is opened inside the child on the first request. run_until_complete does not poll self.running, so shutdown's 1 second join often ends in terminate() during a call.

Database

DatabaseManager stores users, face_embeddings, voice_embeddings, and chat_history in ./database/identities.db. Foreign keys cascade. START_WITH_SAMPLE_DATA is true: startup loads Tiger's sample voice embeddings, and Ctrl+C calls clear_db() before the workers stop. That delete wipes the live file, including identities created during the run.

Dashboard

The page shows coordinator and system logs, worker logs, identity rows, and recent chat. It also renames, deletes, and looks up faces. Routes are in frontend/AGENTS.md. It reads log_queue and the same sqlite file on its own connections.

install_log_interceptor keeps the real print and put_nowaits onto log_queue. _log_drain_loop broadcasts those dicts. _db_poll_loop pushes a sqlite snapshot every 5 seconds on the same socket. That snapshot is a separate read, not a commit shared with save_chat_history or save_face_embedding.

Where the logic lives

The worker file is the sequence: workers/audio.py, workers/vision.py, workers/coordinator.py, workers/api_worker.py. Helpers take the owned objects as arguments. Audio decisions are in workers/audio_utils/ (vad.py, utterance.py, speaker.py). Vision decisions are in workers/vision_utils/ (pipeline.py, tracks.py, matching.py, inspireface_processor.py). Coordinator decisions are in workers/coordinator_utils/handlers.py and association.py. Event dicts for the API worker are built in workers/api_utils/commands.py. core/ holds config, SharedMem, and the log interceptor.

Not on the hot path

voice_embedding_creator.py writes a Redimnet .npy from a wav. The live embed is voice_embedding in vad.py. get_embedding.py extracts one face from a sample image. facial_processing_demos is not in this checkout, and VisionWorker does not import it. tests/test_openai_tool.py, tests/test_openai_memory.py, and tests/test_api_worker_live.py call OpenAI outside the running pipeline.

Limits and directions

  • Limit Workers are multiprocessing.Process and the code never calls set_start_method. On macOS the default is spawn, so the child only unpickles what __init__ stored. InspireFace, Silero, Redimnet, and Parakeet are created in setup() inside that child.
  • Limit Shutdown joins every worker for 1 second and terminates whoever is still alive. APIWorker blocks in run_until_complete for the HTTP call and does not see running until the call returns, so client.close() is skipped.
  • Direction Join the API worker through the end of run() without terminate, so the in-flight call finishes and client.close() runs.
  • Limit START_WITH_SAMPLE_DATA is true. On Ctrl+C, main.py calls clear_db() on ./database/identities.db before workers stop. DELETE FROM users cascades to embeddings and chat history, including people registered in that run.
  • Direction Stop calling clear_db() on the live database when sample data was loaded.
  • Limit An existing name is checked with closest_frame and face_matches, or one cosine in voice_matches (0.30). identify_speaker is one embedding against stored means, plus a last-speaker bias. associate_voice returns an id or None from a 1.0 second window, a 0.3 speaking ratio, or a 0.8 presence ratio. Live faces omit is_speaking, so the speaking ratio stays at zero. This is not a tracked conversation.
  • Direction Return an association score from associate_voice with the id, instead of a bare id.
  • Limit End of sentence is silence_count >= SILENT_CHUNK_THRESHOLD, and that constant is 1. One quiet chunk calls finish_utterance.
  • Direction Decide the sentence boundary with more than SILENT_CHUNK_THRESHOLD.
  • Limit ANALYZE_MEMORY and memory_event already build a memory_result with subject and facts. The coordinator never enqueues that command, and handle_event has no memory_result handler. Facts are not stored.
  • Direction Apply that memory_result as a small per-person fact record. The API worker already shapes the event.
  • Limit This checkout has no hardware/ tree. Imported hardware/src/udp.cpp uses WS_FRAME_VIDEO 0x01 and WS_FRAME_AUDIO_TX 0x02. core/config.py uses HEADER_VISION and HEADER_AUDIO for the same bytes. Nothing compares them. The device and the host meet only at that byte.
  • Direction One contract test that the header bytes in hardware/src/udp.cpp match core/config.py.
